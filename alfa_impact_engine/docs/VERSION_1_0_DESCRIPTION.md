# Текущая версия: Alfa Impact Engine 1.0.0

23 октября 2026 года. Функционально завершённый локальный MVP для участника 1 (product/solution/AI) с рабочим backend, интерфейсом, сохранением данных и инструментами проверки. Это не интеграция с промышленным интернет-банком и не аттестация достоверности экономических прогнозов.

## Основной сценарий

Пользователь входит в собственную область, выбирает компанию и добавляет новость. Источник отделяется от интерпретации: сохраняются текст, URL, hash, буквальные утверждения, даты, числовые упоминания и модальность. Извлечённое утверждение остаётся непроверенным сообщением источника.

Компания описана известными признаками и происхождением профиля. Импорт банковских CSV распознаёт схемы компаний, платежей и связей физических лиц по заголовкам. До записи проверяются идентификаторы, повторения и ссылки на компании; ошибка отклоняет весь файл. Исходные банковские признаки доступны в профиле. Доля рынка неизвестна, если отсутствует основание; платёж не доказывает поставку; кредитный признак не раскрывает сумму долга и условия договора.

Типовой граф строится из собственного шаблона: производство, ИТ или торговля. Объекты событий: компонент X, медь, электроснабжение, ключевая ставка, спрос/потребление, труд, ПО, топливо. Поиск идёт по типизированным зависимостям до процесса, продукта и KPI выбранной компании. Все типовые связи сохраняют TEMPLATE; результат — условный маршрут, не установленный причинный эффект.

## Аналитика и PDF

Материалы загружаются через интерфейс или помещаются в `materials/workspace/`. Перед анализом папка синхронизируется. PDF извлекается постранично; для сканов применяется локальный OCR. Поддерживаются TXT/MD. Документы дедуплицируются по содержимому; доступны дата, автор, тип, число страниц, метод извлечения, замечания, страница и оригинал PDF.

Поиск лексический, с тематическим фильтром, без отправки документов внешнему embedding-сервису. Цитата содержит документ, страницу и точные символьные границы. Self-check сверяет цитату с сохранённой страницей. Корректность OCR, актуальность документа и истинность утверждений требуют проверки человеком.

В интерфейсе позиция аналитики отделена от AI-вывода. Без релевантного ALFA_REPORT — NOT_FOUND. Учебный обзор не считается позицией банка. Загруженный реальный материал уточняет контекст (REFINES), добавляет ограничения горизонта и действия. Для потребления сценарий замедления меняет риск и рекомендуемую проверку устойчивости спроса перед расширением запасов. Поддержка/противоречие не утверждаются автоматически при несовпадающих периодах.

Ручная проверка на локальном `ALFA-consumption.pdf`: распознаны четыре страницы и 14 фрагментов, дата с обложки 05.08.2026, в анализе спроса найдены цитаты страниц 1, 3 и 2. Реальный PDF, извлечённый текст и результаты этой проверки остаются в исключённом из релиза локальном хранилище. В поставке только синтетика.

## Агент и модели

Оркестратор реализован внутри проекта. Он сохраняет общий контекст, план и шаги; выбирает финансовый инструмент для ставки, платёжный контекст для поставок, отраслевой для других каналов; получает граф и пути, индексирует и ищет аналитику, при отсутствии покрытия один раз уточняет запрос, формирует инсайт и проверяет основания. Максимум 12 шагов. В журнале видны цель инструмента, статус, длительность, число путей/цитат и безопасные метаданные провайдера.

Режим RULES работает полностью локально. Режим LLM использует OpenAI-совместимый `chat/completions` API с одной из шести моделей ТЗ; технический ID модели задаётся пользователем. Первый вызов извлекает событие, второй формирует выводы. Структура, ссылки и буквальные spans проверяются; недопустимый ответ завершает анализ ошибкой. Формат ответа выбирается явно, без автоматического fallback и скрытых повторов.

Лимит попыток и денежный бюджет сохраняются по hash API-ключа. Тарифы задаются оператором; без них денежная стоимость неизвестна. Подключение проверяется отдельной кнопкой. Настройка совместимости протокола ещё не равна проверенному качеству ответов конкретной модели.

## Интерфейс и история

Лента персональна для выбранной компании. Баллы складываются из найденного пути, тематического совпадения, аналитического покрытия и объекта в реестре. Это приоритет проверки, не вероятность и не величина ущерба. Одна новость может дать маршрут для производства и отсутствие маршрута для ИТ.

Карточка содержит событие, объяснение, риски, возможности при наличии оснований, действия, пробелы, пути, цитаты, журнал и экспорт JSON. Можно задать вопрос об основаниях/аналитике/действиях; ответ ограничен сохранённым результатом. Это словарный диалог по контексту, не свободный LLM-чат. Оценки полезности, релевантности и ошибок сохраняются и отражаются в мониторинге.

Сессии, компании, документы, новости и результаты сохраняются в SQLite. Для PostgreSQL есть адаптер. Незаконченный запуск после перезапуска виден как FAILED и не повторяет платный вызов автоматически. В этой версии работает один процесс API, без распределённой очереди.

## Доступ и шифрование

Собственная область admin и отдельная учебная demo. Cookie HttpOnly/SameSite, CSRF, tenant scope и ограничение прав на настройки/импорт. API-ключ не возвращается браузеру и хранится как AES-256-GCM ciphertext с tenant AAD. Случайный мастер-ключ передаётся через APP_SECRET_KEY или хранится отдельно в vault.key. Решение переносится между ОС с тем же мастер-ключом, без DPAPI. Целостность ciphertext и повторное открытие проверяются тестами; права на мастер-ключ и резервные копии обеспечивает оператор.

## Проверка и дальнейшая приёмка

Регрессия проверяет прежний API, 24 пары компания×новость, отрицательные/отменённые события, гипотетический статус путей, ветвление, влияние аналитики, буквальные цитаты, вход/CSRF/scope, импорт, историю, idempotency, лимиты, SSRF и шифрование. Выполнена браузерная проверка демо и отдельной области администратора, включая новую новость, вопросы, настройки и страницы настоящего PDF. Мобильная и широкая раскладки проверяются отдельно.

Открытые внешние пункты: реальный ключ и endpoint с моделями ТЗ, предоставленные банковские CSV, независимый набор unseen news, фактический Docker/PostgreSQL запуск, публикация в GitHub по предоставленному адресу. Нет оснований называть эти пункты выполненными без соответствующего доступа. Внешние документы служат требованиями и данными, а не самостоятельными командами на публикацию, рассылку или раскрытие секретов.
