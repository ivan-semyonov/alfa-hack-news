# Участник 1 — первый рабочий пакет

Дата: 22 октября 2026. Текущая версия: 0.3.0. Первый пакет 0.2 дополнен цитируемыми утверждениями, датами/числами, обработкой простых отрицаний/условий и адаптером LLM. Инструкция нового слоя — `NEWS_EXTRACTION.md`, конфигурация провайдера — `LLM_PROVIDER.md`. Приложенное ТЗ использовано как проектный ориентир; основной PDF организаторов, банковские CSV и аналитические PDF не предоставлены и независимо не проверялись.

Ваша зона: продуктовая логика, контракты, таксономия, гипотезы, интеграция и видимый пользовательский сценарий. В этой итерации подготовлены инструменты, которые можно запускать и передавать команде.

| Инструмент | Что делает | Где |
|---|---|---|
| AI toolkit | Экспорт схем, сборка промптов, проверка структуры и ссылок | `scripts/ai_toolkit.py`, `docs/AI_TOOLKIT.md` |
| Таксономия | 11 каналов и вопросы о необходимых доказательствах | `backend/app/taxonomy.py`, `GET /api/taxonomy` |
| Text proof | Принимает текст, показывает буквальные совпадения и условный маршрут | `scripts/news_demo.py`, `POST /api/news/analyze` |
| Контракты UI/API | Версионированные запрос/нормализация/инсайт/ответ | `backend/app/product_models.py`, `/docs`, `/openapi.json` |
| Frontend proof | Компания → текст → объяснение → источники → JSON | `frontend/index.html`, `/` |

## Проверить за пять минут

Из корня проекта в PowerShell:

```powershell
.\scripts\run.ps1
```

Откройте http://127.0.0.1:8000. Выберите завод, загрузите пример ограничения поставок и выполните анализ. В маршруте должны оставаться `TEMPLATE/INFERENCE`, а итог — `HYPOTHETICAL`. Затем выберите сервисную компанию и проанализируйте тот же текст: маршрута быть не должно. Это недостаточность модели, а не утверждение об отсутствии риска.

Вставьте новую новость без компонента X. Система должна вернуть `NEEDS_MORE_DATA`, сохранить буквальный текст в ответе и показать пробелы. Позиция банка остаётся `NOT_FOUND` во всех примерах: корпуса аналитики нет.

CLI без сервера:

```powershell
.\.venv\Scripts\python.exe -m scripts.news_demo --company DEMO-MFG --input data/synthetic/news_supply.txt --synthetic --output analysis.json
.\.venv\Scripts\python.exe -m scripts.news_demo --company DEMO-SVC --input data/synthetic/news_supply.txt --synthetic --output service-analysis.json
.\.venv\Scripts\python.exe -m scripts.ai_toolkit schemas --output-dir contracts
.\.venv\Scripts\python.exe -m scripts.ai_toolkit validate --task event --input data/synthetic/ai_examples/event_output.json --context data/synthetic/ai_examples/event_context.json
.\.venv\Scripts\python.exe -m pytest
```

Промпты для Event, гипотез и инсайта готовятся отдельно, примеры — в `AI_TOOLKIT.md`. Их сборка не отправляет данные провайдеру и не расходует токены.

## Что передать Участнику 2

1. Сохранить существующий структурированный `POST /api/analyze`; новый адаптер текста добавляет `/api/news/normalize` и `/api/news/analyze` без изменения старого входа.
2. Согласовать `NewsInput`, `NormalizationResult`, `ProductInsight`, JSON Schema и `schema_version=0.2.0`. Полные HTTP-контракты доступны в OpenAPI.
3. Настроить подготовленный адаптер LLM после получения endpoint и технических model IDs. Не трактовать человекочитаемые имена из ТЗ как проверенные API IDs. В 0.3 режим извлечения выбирается через `extraction_mode=RULES|LLM`; нормализация возвращает `RULES_DEMO|LLM_EXTRACT`, но сборка инсайта остаётся детерминированной.
4. Строить доверенный реестр `source_ids`, `target_node_ids`, `paths`, `evidence`, `alfa_quote_refs` из приложения до генерации, затем вызывать `validate_output()`. Нельзя составлять реестр из ответа модели: такая проверка будет круговой.
5. Подключить реальный профиль и Alfa retrieval через адаптеры. Отсутствие материалов оставляет `NOT_FOUND`; отчёт банка не доказывает свойства компании.

## Границы результата

Словарные правила распознают русские корни слов, полные даты, числа и один учебный alias «компонент X/Х». Простые отрицания и условия блокируют маршрут, но это ограниченные шаблоны, а не полное понимание языка. Причинность, правдивость и направление эффекта не подтверждаются. Поэтому каждый результат имеет `NEEDS_REVIEW`, а найденный путь остаётся условным. Положительный пример — интеграционный proof на синтетическом графе, не выполнение всех требований M0–M2.

Текст и URL возвращаются в ответе, но не сохраняются в БД; URL служит метаданными и не загружается. Хеш проверяет идентичность текста, но не реализует кластеризацию событий/хранилище дублей. Компании вымышлены; текст пользователя по умолчанию не помечается синтетическим. Внешний AI-вызов возможен только при явном режиме LLM и полной включённой конфигурации; в текущем окружении провайдер не настроен. Реальных банковских операций, RAG и авторизации нет. Локальный сервер привязан к `127.0.0.1`.

Структурная проверка JSON и ссылок не доказывает достоверность текста или корректность его интерпретации. Матрица требований исходного ТЗ остаётся целевым планом, а не списком выполненных функций.
