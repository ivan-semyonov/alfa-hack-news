# Архитектура 1.0.0

Один FastAPI процесс, интерфейс на HTML/CSS/JS без CDN. `product_api.py` проверяет сессию, роль, CSRF и tenant до вызова сервиса. `ResearchService` объединяет инструменты, но не имеет инструментов банковских операций. SQLite — локальное хранилище; тот же параметризованный repository работает с psycopg/PostgreSQL по DSN.

## Жизненный цикл

`POST /api/v1/analyses` атомарно сохраняет вход, новость с hash и запись RUNNING. Idempotency key защищает повторную отправку; для разных входов тот же ключ запрещён. Разрешён один активный запуск на область. BackgroundTasks исполняет ограниченную последовательность; браузер опрашивает сохранённый результат. Статусы: RUNNING, COMPLETED, NEEDS_MORE_DATA, FAILED. После перезапуска незаконченные задания получают SERVER_RESTART и не повторяют платные запросы.

Шаги: профиль → извлечение → выбор финансового/платёжного/отраслевого контекста → граф → допустимые пути → синхронизация PDF → поиск → максимум один уточняющий поиск → синтез → self-check. До 12 шагов. План и причины выбора инструментов наблюдаемы; скрытые рассуждения модели не сохраняются.

В RULES извлечение и синтез локальные. В LLM два последовательных schema-bound вызова через `llm_provider.py`: извлечение с проверкой буквальных spans, затем синтез с допустимыми path/citation IDs. Ответ с чужой ссылкой или числовым утверждением в свободном тексте отклоняется. Это структурная проверка, а не доказательство семантической истинности.

## Модель знаний

`industry.py` — собственные шаблоны и alias registry. Ресурс → процесс → продукт → KPI строится обратным обходом REQUIRES/DEPENDS_ON/CONTRIBUTES_TO в scope компании. Платёжные связи не участвуют в распространении влияния. FACT — свойство в источнике; TEMPLATE — типовая зависимость; HYPOTHESIS — предположение; REJECTED не допускается в путь. Неизвестны коэффициенты, сила зависимости, доля рынка и финансовый эффект.

`retrieval.py`: content-hash дедупликация, страницы, фрагменты по 1200 символов с шагом 1000, тематический фильтр, простой лексический скоринг. До 4 цитат, не больше одной на страницу документа; документ/страница/offset/quote проверяются по сохранённому тексту. OCR — Windows OCR либо Tesseract; нераспознанная страница не используется как доказательство. Лимиты: PDF 10 МБ/200 страниц/1 млн символов, OCR первых 20 страниц; до 40 файлов за синхронизацию, 200 документов и 5000 фрагментов в поиске. Для большого корпуса требуется замена поискового адаптера.

Аналитика имеет тип ALFA_REPORT/PUBLIC/SYNTHETIC, автора, дату, provenance. Тип задаёт оператор, издатель автоматически не удостоверяется. Без реального релевантного ALFA_REPORT — NOT_FOUND. При наличии материала — REFINES с цитатами, дополнительными вопросами и ограничениями горизонта. Для спроса сценарий замедления добавляет отдельный риск и проверку устойчивости спроса до изменения запасов. Нет автоматического вывода SUPPORTS/CONTRADICTS без семантической проверки и сопоставления периодов.

## Данные и ограничения эксплуатации

Все запросы новых сущностей используют tenant. Пароли PBKDF2-SHA256; session tokens сохраняются hash; API-ключ AES-256-GCM, мастер отдельно. Исторический API изолирован на фиксированных synthetic fixtures. Логи провайдера содержат технические метрики, не ключ/текст/тело ошибки.

Вопросы — ограниченный словарный маршрутизатор по сохранённому результату, без общего чата. Импорт CSV атомарный, FK проверяются внутри области, сумма Decimal хранится в исходной единице; период/единица задаются явно или неизвестны. Person links сохраняются как связи, без деанонимизации.

Один локальный исполнитель, без гарантии доставки при аварии и без multi-worker. Для промышленной системы нужны SSO, роли на отдельные компании, общая очередь/leases, аудит эксплуатации, нагрузочная и независимая AI оценка. SQLite не предназначен для горизонтального масштабирования; адаптер PostgreSQL ещё требует приёмки на живом сервере.
