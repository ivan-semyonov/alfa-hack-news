# Состояние реализации — 22.10.2026, версия 0.3.0

## Готово

- Исходный пакет 0.1: Pydantic Company/Event/Graph/Evidence/ImpactPath, две синтетические компании, два структурированных события, NetworkX с разрешённым обратным обходом, FastAPI, DDL и CSV preflight.
- Участник 1: версия HTTP-контрактов текста/нормализации/инсайта, таксономия 11 каналов, промпты Event/Hypotheses/Insight, точный перечень моделей из приложенного ТЗ, строгий валидатор структуры/границ/ссылок.
- CLI: `scripts.ai_toolkit` (таксономия, JSON Schema, промпты, проверка ответов) и `scripts.news_demo` (текст → JSON анализа без сервера).
- `/api/news/normalize`, `/api/news/analyze`, `/api/taxonomy`; исходный `/api/analyze` сохранён.
- Интерфейс: выбор компании, текст новости, примеры, условный маршрут со статусом каждого звена, риски/пробелы/следующие действия, источники и экспорт JSON. Смена контекста отменяет устаревший запрос и очищает результат.
- JSON Schema в `contracts/`, пример результата в `data/synthetic/analysis_sample.json`, инструкция роли в `docs/PARTICIPANT_1.md`, решения в `docs/DECISIONS.md`.
- Локальное `.venv`, скрипт запуска Windows и снимок точных зависимостей `backend/requirements-lock.txt`.
- Извлечение `SOURCE_ASSERTION`: цитаты участников/действий/объектов, даты с проверенной нормализацией, числа с единицей и явно указанным периодом. Source spans связаны с исходным текстом; результат всегда требует проверки.
- Простые отрицания/условия и совпадения в разных предложениях блокируют маршрут; обрезанный или объединённый ответ модели дополнительно проверяется по исходным фрагментам.
- Явный режим `LLM` через конфигурируемый HTTP-адаптер: allowlist, отдельный API ID, строгая схема, проверка цитат, лимиты попыток/токенов, оценочный бюджет при заданных тарифах, безопасные ошибки. По умолчанию выключен.
- `/api/news/extract`, CLI `scripts.extract_news` и `scripts.evaluate_extraction`, четвертая схема `contracts/extraction.schema.json`, регрессионный набор и отчёт.

## Проверено

- 120 pytest-тестов: исходные graph/API/golden/CSV, AI-контракты, извлечение/цитаты, ошибки и лимиты провайдера через MockTransport, HTTP-интеграция, отказ от маршрута, длинные входы, некорректный Unicode, ошибки JSON и отсутствие исходного текста в ошибке CLI. Реальных внешних запросов при проверках нет.
- 14 синтетических регрессионных текстов, 28 запусков для двух компаний: все ожидания выполнены; 192 из 192 возвращённых фрагментов совпадают с источником. Набор составлен разработчиками и не измеряет общую точность AI.
- CLI: генерация схем, подготовка промпта, валидный и невалидный JSON, анализ текстового примера для двух компаний.
- Живой браузер: форма, положительный маршрут завода, раскрытие источников, смена компании со сбросом результата, отсутствие маршрута для сервисной компании на той же новости.
- Браузер 0.3: отрицание без маршрута, цитируемые утверждения, ISO-дата и 120 тонн в месяц, недоступный режим LLM при отсутствующей конфигурации. Найденная ошибка инициализации списка режимов исправлена и повторно проверена.
- `pip check` не обнаруживает несовместимых зависимостей. Есть предупреждение deprecation в стороннем Starlette TestClient/AnyIO, не сбой тестов.

## Границы текущего proof

Нормализация по умолчанию использует `RULES_DEMO`; явный режим модели — `LLM_EXTRACT`. Извлекаются утверждения источника, а не независимо подтверждённые факты. Простые даты/отрицания/условия обрабатываются ограниченными шаблонами; полнота, семантика, актуальность, направление и сила эффекта не гарантируются. Каждый результат имеет `NEEDS_REVIEW`. Alias графа ограничен компонентом X; пути остаются гипотетическими. Инсайт составляется по шаблону в обоих режимах. Никаких калиброванных вероятностей или прогнозов потерь нет.

Адаптер LLM испытан только на синтетических ответах. Endpoint, ключ и технический model ID не предоставлены; реальная связь/совместимость не проверена. `.env.example` — образец переменных, автоматической загрузки файла нет. При отсутствии доступа или невалидном ответе запрошенный режим LLM возвращает 503 без скрытого fallback. Тарифы неизвестны; контроль денег при их настройке ограничен одним процессом, не общим ключом команды.

Компании/граф вымышлены; текст пользователя имеет отдельный `is_synthetic=false` по умолчанию. Ссылки принимаются только как метаданные: сетевой загрузки нет. Есть content hash, но нет хранилища/дедупликации событий. Результат возвращается в ответе/экспорте, а не сохраняется в БД.

## Не готово

- Реальные банковские CSV, их импорт, CompanyRepository и подключение PostgreSQL. Исходных файлов нет.
- Полноценное извлечение фактов из произвольной новости, RSS/URL ingestion, event clustering и dedup.
- Проверенные вызовы реальной разрешённой LLM и совместимость endpoint/model IDs; распределённый контроль стоимости общего ключа.
- Alfa RAG: фактические аналитические PDF не предоставлены, статус банка всегда `NOT_FOUND`.
- Самостоятельный agent planner, инструментальные маршруты, self-check семантики, динамическое расширение графа.
- Авторизация/изоляция tenants, production rate limiting/monitoring, сохранение анализов и уточняющий диалог.
- Ранжированная новостная лента, React/TypeScript приложение и полный M2 UX.
- Расширенный вручную размеченный golden set и измерение превосходства над LLM baseline.
- Docker clean install: Docker CLI в этом окружении отсутствует; Dockerfile/Compose из стартового архива не запускались.

Матрица требований `TECH_SPEC.md` остаётся целевой. Версия 0.3 расширяет пакет Участника 1 и не является готовым решением хакатона. Новый слой и интерфейсы описаны в `NEWS_EXTRACTION.md`, адаптер — в `LLM_PROVIDER.md`, проверочные примеры — в `EVALUATION.md`.
