# Извлечение утверждений источника — версия 0.3.0

Новый слой выделяет утверждения, участников, действия, объекты, даты и численные величины с точными фрагментами исходного текста. Это разметка источника, а не установление истинных фактов. Для каждого утверждения сохраняется `verification_status=SOURCE_ASSERTION`, для результата — `review_status=NEEDS_REVIEW`.

По умолчанию работает `RULES`: локальные словарные шаблоны, без отправки данных. `LLM` требует явно выбранного режима и полной включённой конфигурации провайдера. Инсайт и обход графа в обоих случаях остаются детерминированными. Реальная модель в текущем окружении не настроена; её совместимость не проверена.

## Данные и проверки

- `SourceSpan`: идентификатор источника, нулевые индексы `[start:end]` в Python Unicode code points и точная цитата. Индексы не являются байтами или JavaScript UTF-16 offsets. Проверяется равенство срезу исходной строки.
- `SourceAssertion`: цитируемый фрагмент; необязательные `actor/action/object`, каждый со своей цитатой внутри этого фрагмента; модальность `ASSERTED`, `NEGATED`, `POSSIBLE` или `UNKNOWN`.
- `DateMention`: исходная цитата, роль `EVENT/PUBLICATION/UNSPECIFIED`, календарная дата или `null`. Локальные правила не назначают роль по догадке. Нормализуются корректные YYYY-MM-DD, DD.MM.YYYY и русская дата с годом. «Вчера/завтра» остаются без календарного значения; дата запуска не подставляется.
- `QuantityMention`: цитаты величины, числа, единицы и периода. Например, `120`, `тонн`, `в месяц`. Пересчётов, новых процентов и финансовых прогнозов нет. Отсутствующая единица или период — `null`. Процентные пункты сохраняются отдельно от процентов.
- `TargetMention`: только разрешённый учебный alias компонента X/Х → `RESOURCE_X`, ссылка на утверждение и фрагмент. Модель не может создать неизвестный ID графа.
- Каналы должны иметь цитируемые основания, кроме одиночного `OTHER`. Идентификаторы утверждений уникальны; посторонние поля отклоняются.

Локальная обработка ограничена 12 фрагментами по 4000 символов, 20 датами/величинами/упоминаниями объекта и 22 основаниями каналов. По каждому каналу берутся до двух словарных совпадений. Ограничение количества/длины отражается в пробелах, слишком длинные совпадения пропускаются. Весь исходный текст остаётся доступным в нормализации и HTTP-анализе. Вход ограничен 20 000 символами; некорректный Unicode отклоняется.

Перед допуском к графу объект, действие изменения и основание канала SUPPLY должны находиться в одном исходном фрагменте. Простое отрицание, отмена или условие блокируют маршрут. Дополнительно проверяется исходный фрагмент, чтобы обрезанная моделью цитата не могла удалить предшествующее «не» или объединить объект одного предложения с действием другого. Это консервативный фильтр, а не универсальное понимание сложного языка. Все пути учебного графа остаются гипотетическими.

## HTTP

`POST /api/news/extract` принимает `text`, опциональные `title`, `source_url`, `is_synthetic`, `extraction_mode=RULES|LLM` и возвращает `ExtractionResult`. Компания для извлечения не нужна.

`POST /api/news/normalize` возвращает источник, `extraction` и совместимое событие для графа. `POST /api/news/analyze` дополнительно требует `company_id`, возвращает нормализацию, анализ и инсайт. Новые оболочки имеют `schema_version=0.3.0`; контракт детерминированного инсайта пока остаётся 0.2.0 и `RULES_DEMO`.

`GET /api/health` показывает только наличие конфигурации, без сетевой проверки и без секретов. Отсутствие/ошибка модели, невалидный JSON и непрошедшие проверку цитаты дают 503. Автоматического переключения на правила и повторной отправки нет. Ошибки входа возвращают 422 без отражения исходных значений новости в сообщении.

В LLM передаются текст/заголовок новости, отметка синтетики, схема и alias-реестр. Профиль выбранной компании, граф, банковские признаки и URL источника этому адаптеру не передаются. Публикация по URL не загружается.

## CLI

Из корня проекта в PowerShell:

```powershell
.\.venv\Scripts\python.exe -m scripts.extract_news schema --output contracts/extraction.schema.json
.\.venv\Scripts\python.exe -m scripts.extract_news prompt --news data/synthetic/news_dated.txt --synthetic --output prompt.json
.\.venv\Scripts\python.exe -m scripts.extract_news extract --news data/synthetic/news_dated.txt --synthetic --output extraction.json
.\.venv\Scripts\python.exe -m scripts.extract_news validate --news data/synthetic/news_dated.txt --synthetic --input data/synthetic/ai_examples/extraction_output.json
.\.venv\Scripts\python.exe -m scripts.news_demo --company DEMO-MFG --input data/synthetic/news_dated.txt --synthetic --output analysis.json
.\.venv\Scripts\python.exe -m scripts.evaluate_extraction
```

Команда `prompt` не вызывает модель. Для `validate` нужен именно JSON `ExtractionDraft` без обёртки результата; исходный текст и метаданные должны совпадать с использованными при подготовке промпта, поскольку от них зависит source ID. Код выхода: 0 при успехе, 2 при невалидном входе/ответе, 3 при недоступной модели. Невалидные данные не печатаются в ошибке.

После настройки среды модель вызывается только явно:

```powershell
.\.venv\Scripts\python.exe -m scripts.extract_news extract --mode LLM --news data/synthetic/news_dated.txt --synthetic --output extraction.json
```

Переменные и ограничения транспорта описаны в `LLM_PROVIDER.md`. `.env.example` — образец, приложение не читает этот файл автоматически. Необходимые значения следует передать окружению процесса сервера или CLI. Модель должна поддерживать заданный протокол и JSON Schema. Цена без тарифов остаётся неизвестной; денежный лимит при тарифах оценивается в пределах одного процесса и не гарантирует контроль общего ключа команды.

## Ограничения

Точность source spans подтверждает происхождение текста, но не истинность утверждения, правильность модальности, роли даты или экономического смысла количества. Возможны консервативные отказы и пропуски: один alias, ограниченный словарь, неполная обработка отрицаний/условий, ограничение размера. Финансовая оценка, новые зависимости компаний, поисковый агент, хранение истории и Alfa RAG не реализованы.

Регрессионный набор разработчиков описан в `EVALUATION.md`; это не независимая оценка качества LLM.
