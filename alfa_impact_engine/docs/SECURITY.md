# Безопасность и переносимое шифрование

## Ключи

API-ключ шифруется стандартным AES-256-GCM из `cryptography`: случайный 256-битный мастер-ключ, новый 96-битный nonce для каждого сохранения, аутентификация содержимого и tenant через AAD `alfa-provider:v1:<tenant>`. Формат `aesgcm:v1:<base64(nonce+ciphertext+tag)>`. Подмена ciphertext, неверный мастер-ключ и перенос шифротекста в чужую область отклоняются. Секрет возвращается только серверному адаптеру.

Мастер-ключ загружается из `APP_SECRET_KEY` (URL-safe Base64 от 32 случайных байтов) или создаётся атомарно в `.runtime/vault.key`. Unix-файл создаётся с mode 0600. На Windows права доступа определяются ACL каталога; chmod не заменяет ACL. Шифрование одинаково работает на Windows/Linux/macOS, не использует DPAPI, системный keychain или идентификатор устройства.

Проверка: `python scripts/check_vault.py`. Тесты дополнительно копируют мастер-ключ в другой каталог, создают новый экземпляр Vault, проверяют расшифровку, уникальность nonce, повреждение и чужой tenant. Проверка Linux как целой среды ещё не выполнена.

Для переноса: остановите сервер, скопируйте БД, `.runtime/documents`, `materials` и отдельно мастер-ключ; задайте тот же `APP_SECRET_KEY` или восстановите `vault.key`. Пути оригиналов PDF восстанавливаются относительно нового runtime-каталога. Сделайте резервную копию ключа отдельно от БД. Если потерян ключ, прежние секреты не восстанавливаются; в настройках можно ввести новый API-ключ. Смена мастер-ключа требует повторного ввода API-ключа, автоматической ротации нескольких ключей нет.

Локальный файл мастер-ключа обеспечивает переносимость, а не защиту от владельца всего компьютера. Доступ к БД вместе с мастер-ключом позволяет расшифровку. Для сервера задавайте APP_SECRET_KEY через менеджер секретов и ограничивайте доступ к процессу/томам. Не помещайте ключ, `.env`, рабочую базу и PDF в Git. Нет обещания HSM/KMS или защиты от администратора ОС.

## Доступ и недоверенный контент

HttpOnly SameSite=Strict cookie, восемь часов, Secure на HTTPS. Случайный session token хранится в БД как SHA256, logout отзывает его. CSRF header сверяется с сессией, Origin/Fetch-Site проверяются на изменениях. Первичная настройка admin только loopback или APP_ADMIN_PASSWORD. Пароль PBKDF2-SHA256/250000 с уникальной солью. Вход ограничен 30 попытками/10 минут/IP в процессе. Tenant берётся из сессии, не из тела запроса; demo отделён и не имеет права настройки/импорта. Компания в рабочей области доступна её администратору; тонких разрешений по компаниям/корпоративного SSO нет.

PDF, новости, ответы моделей и тексты CSV считаются данными. UI экранирует строки. Инструкции внутри источника не запускаются. У агента только ограниченные read/context tools, нет shell/банковских/произвольных HTTP инструментов. Системная инструкция модели не гарантирует защиту от prompt injection, поэтому дополнительно проверяются структура, источник цитат и ссылки. Семантическая галлюцинация со ссылкой на формально допустимый источник остаётся риском и требует ручной проверки.

Загрузка статьи: явное действие пользователя, только HTTPS/443, все DNS-адреса публичные, соединение привязано к проверенному IP, TLS проверяется по исходному hostname; без прокси/редиректов, 10 секунд, 2 МБ. Ключ провайдера туда не передаётся. API провайдера настраивает только admin, HTTPS или явный loopback HTTP; redirects/proxy env отключены. API admin доверен выбрать получателя ключа; смена адреса требует повторного ввода ключа.

## Ресурсы и эксплуатация

Лимит HTTP-тела 16 МБ, ограничены PDF/OCR/текст/число шагов/токены/timeout/ответ API. Попытки резервируются до вызова и не возвращаются при сетевой ошибке, что предотвращает неограниченные повторения. Суточные лимиты общие по hash ключа и хранятся в БД, сутки UTC. При известных тарифах резервируется максимальная стоимость; без двух тарифов денежная стоимость UNKNOWN, действует лимит попыток. Биллинг провайдера — окончательный источник стоимости, локальный счётчик не видит другие приложения с тем же ключом.

Парсеры PDF и OCR выполняются локально под правами процесса, без отдельной sandbox VM; вредоносный или сложный PDF может потребовать изоляции и обновлений зависимостей. Публикация приложения за пределами localhost требует TLS reverse proxy, ограничения доступа, резервных копий и проверки целевой среды. Docker использует непривилегированного пользователя. Не используйте несколько Uvicorn workers в этой версии. Прерванный запуск помечается FAILED, платный вызов не повторяется автоматически.

Исходники/архив включают только allowlist; `.runtime`, `.env`, банковские CSV и PDF исключены. Предусмотрены тесты CSRF, scope, SSRF, tamper, idempotency, лимитов и отсутствия секретов в ответах. Полноценный внешний pentest не проводился.
