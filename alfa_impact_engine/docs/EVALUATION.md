# Регрессионная проверка извлечения — версия 0.3

Набор `evaluation/extraction_cases.json` содержит 14 синтетических текстов, составленных при разработке. Каждый текст проверяется для завода `DEMO-MFG` и сервисной компании `DEMO-SVC`: всего 28 запусков анализа. Это проверочные примеры разработчиков, а не независимо размеченный экспертами golden set.

Проверяются положительный канал поставок компонента X, отсутствие маршрута для второй компании, нерелевантная новость, финансирование без известного долга, явное отрицание, отмена ограничения, условное событие, совпадения в разных предложениях, неизвестный ресурс, даты, проценты, Unicode и инструкции внутри недоверенного текста.

Из корня проекта в PowerShell:

```powershell
.\.venv\Scripts\python.exe -m scripts.evaluate_extraction
.\.venv\Scripts\python.exe -m scripts.evaluate_extraction --output evaluation/extraction_report.json
.\.venv\Scripts\python.exe -m pytest backend/tests/test_extraction_evaluation.py
```

Оценка вызывает настоящий `analyze_news()` в режиме `RULES`, используя текущий синтетический граф. Внешние провайдеры и модели не вызываются. Сеть для выполнения не требуется.

Для каждого запуска проверяются структура `ExtractionResult`, принадлежность результата выбранной компании, ожидаемое наличие маршрута, необходимые тематические каналы и, где задано, модальность утверждения. Даты сравниваются с ожидаемой исходной цитатой и ISO-значением; относительное «Завтра» должно оставаться без вычисленной календарной даты. Для количеств проверяются точные фрагменты числа, единицы и периода, если соответствующее ожидание задано.

Отдельный обход проверяет каждый возвращённый `SourceSpan`: идентификатор источника, корректность границ и буквальное равенство цитаты срезу исходного текста. Утверждения остаются `SOURCE_ASSERTION`, нормализация — `NEEDS_REVIEW`, путь синтетического завода — `HYPOTHETICAL` со значимостью `UNKNOWN`, позиция банка без корпуса — `NOT_FOUND`.

JSON-отчёт содержит `case_count`, `company_runs`, `passed`, `failed`, число структурно валидных запусков, количество проверенных/корректных фрагментов и ошибки по кейсам. Успешное выполнение завершается кодом 0, провал ожидания — кодом 1, некорректный файл или параметры — кодом 2. Тексты новостей в отчёт не копируются.

Успех этого набора подтверждает сохранение конкретных договорённостей и исправлений в текущем коде. Он не измеряет полноту понимания новостей, достоверность источника, качество будущей LLM, правильность причинного вывода или соответствие гипотез реальным процессам. Поэтому отчёт не публикует precision/recall или общую «точность AI».

Для расширения добавляйте независимые примеры с ожидаемыми каналами, маршрутами, модальностями, датами и количествами. Изменение ожиданий должно сопровождаться объяснением продуктового решения; не меняйте разметку только ради зелёного отчёта. Качество смысловой интерпретации и подтверждение evidence должны отдельно проверяться человеком на материалах, не использованных при разработке правил.
